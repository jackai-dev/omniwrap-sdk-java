# OmniWrapSdk

Dependency-free Java 17+ HTTP SDK generated directly from OmniWrap Semantic IR
for `OmniWrap`.

```java
var options = ApiClient.ClientOptions.builder()
    .baseUri(URI.create("https://omniwrap.net"))
    .accessToken(System.getenv("ACCESS_TOKEN"))
    .build();
var client = new ApiClient(options);
```

The SDK uses `java.net.http.HttpClient`, supports injection, asynchronous
`CompletableFuture` methods (`...Async`) and synchronous wrappers, cancellation,
timeouts, retries, API-key/Bearer/Basic authentication, and structured HTTP and
transport errors. It has no runtime dependency outside Java 17.

## Operations

Every operation is reachable both as a flat method named after its operationId
and through a resource accessor grouped by tag (or first path segment), for
example `client.pets().list()`. Each method comes in four shapes: required
arguments only, required arguments plus `RequestOptions`, all arguments
(optional ones accept `null`), and all arguments plus `RequestOptions`; each
shape has an `Async` twin. Required integer, number and boolean parameters are
primitives (`long`, `double`, `boolean`); optional ones are boxed so `null`
omits them.

- `GET /v1/me/context` -> `client.context().getUser(...)` / `client.getUserContext(...)`
- `GET /v1/projects` -> `client.projects().list(...)` / `client.listProjects(...)`
- `GET /v1/projects/{projectId}` -> `client.projects().get(...)` / `client.getProject(...)`
- `POST /v1/projects/{projectId}/source-revisions` -> `client.sources().createRevision(...)` / `client.createSourceRevision(...)`
- `GET /v1/projects/{projectId}/source-revisions/{revisionId}` -> `client.sources().getRevision(...)` / `client.getSourceRevision(...)`
- `POST /v1/projects/{projectId}/configuration-revisions` -> `client.configurations().createRevision(...)` / `client.createConfigurationRevision(...)`
- `GET /v1/projects/{projectId}/configuration-revisions/{revisionId}` -> `client.configurations().getRevision(...)` / `client.getConfigurationRevision(...)`
- `GET /v1/projects/{projectId}/previews` -> `client.previews().list(...)` / `client.listPreviews(...)`
- `POST /v1/projects/{projectId}/previews` -> `client.previews().create(...)` / `client.createPreview(...)`
- `GET /v1/projects/{projectId}/previews/{previewId}` -> `client.previews().get(...)` / `client.getPreview(...)`
- `POST /v1/projects/{projectId}/previews/{previewId}/cancel` -> `client.previews().cancel(...)` / `client.cancelPreview(...)`
- `GET /v1/projects/{projectId}/previews/{previewId}/events` -> `client.previews().getEvents(...)` / `client.getPreviewEvents(...)`
- `GET /v1/projects/{projectId}/previews/{previewId}/logs` -> `client.previews().getLogs(...)` / `client.getPreviewLogs(...)`
- `GET /v1/projects/{projectId}/previews/{previewId}/evidence` -> `client.evidence().listPreview(...)` / `client.listPreviewEvidence(...)`
- `GET /v1/projects/{projectId}/evidence/{evidenceId}` -> `client.evidence().get(...)` / `client.getEvidence(...)`
- `GET /v1/projects/{projectId}/artifacts/{artifactId}` -> `client.artifacts().get(...)` / `client.getArtifact(...)`

Object and `allOf` schemas become records; arrays and maps stay typed. Named string
enums preserve unknown wire values: use `value()` to read the wire value and
`known()` (null for an undeclared value) when branching on declared values.
Because Java has no structural union, named `oneOf`/`anyOf` schemas use a
lossless `Object` wrapper. A `$ref` the normalizer could not resolve (an
external document that was not supplied) is typed as `Object` and carries the
parsed JSON value. OAuth token acquisition and mTLS configuration
helpers, webhook verification and schema validation are not generated.
Automatic pagination is not implemented because this contract has no supported proven pagination plan.

## Errors

Every failure extends `ApiClient.ApiException` (`statusCode`, `headers`,
`body`, `rawBody`, `requestId`, `operationId`, `attempts`, `retryable`). A
non-2xx status is raised as the matching subclass: `BadRequestException`
(400), `AuthenticationException` (401), `PermissionDeniedException` (403),
`NotFoundException` (404), `ConflictException` (409),
`UnprocessableEntityException` (422), `RateLimitException` (429),
`InternalServerException` (5xx); other statuses stay `ApiException`.
`ApiTransportException` (connection failures), `ApiTimeoutException`
(per-request timeout, extends the transport exception),
`ApiResponseTooLargeException` (the configured byte limit) and
`MissingCredentialsException` (no configured credential satisfies the
operation; extends `AuthenticationException`) share the same root.

## Retries

`maxRetries` (default 2, per call `RequestOptions.Builder.maxRetries`) bounds
the retries after the first attempt. A request is retried only when its
operation is idempotent (GET, HEAD, PUT, DELETE, OPTIONS, TRACE, or
`x-omniwrap-idempotent: true`) or it carries an `Idempotency-Key`: the
`idempotencyKey` of its `RequestOptions`, or an operation's declared
`Idempotency-Key` header parameter, whose value wins when both are set. Every
attempt replays the key the first one sent. Connection failures and timeouts
follow the same rule. The server's own verdict wins: `x-should-retry: true` or
`false` overrides the status policy (408, 409, 429 and every 5xx; 425 is never
retried), and its wait is honoured from `retry-after-ms`, then `Retry-After`
(seconds or an HTTP date), then the IETF `RateLimit` reset (`t=` or
`RateLimit-Reset`). Without one, waits back off exponentially with jitter
(500 ms doubling, at most 60 seconds). A server asking for longer than
`maxRetryDelay` (default 60 seconds) gets its error thrown at once, with its
headers and `retryable` flag, since a retry it said would fail only adds load;
`retryBudget` (none by default) caps a whole call, waits included.

`fallbackBaseUris` (none by default) lists ordered alternates to `baseUri`.
Only idempotent operations use them, and only a connection failure, a timeout
or a 5xx moves a call to the next one; a 4xx retry such as a 429 stays on its
endpoint, and the last endpoint serves the remaining attempts. `onAttempt` is
called after every attempt, before any retry wait, with the
`ApiClient.AttemptContext` naming the `operationId`, the `attempt` number, the
`baseUri` it targeted, the `requestUri`, the `statusCode` or transport `error`,
and the `retryDelay` before the next attempt, if any. Whatever the listener
throws, an `Error` such as a failed assertion included, ends the call with it.

```java
import dev.omniwrap.omniwrap.sdk.ApiClient;
import java.net.URI;
import java.time.Duration;
import java.util.List;

var options = ApiClient.ClientOptions.builder()
    .baseUri(URI.create("https://omniwrap.net"))
    .maxRetries(3)
    .maxRetryDelay(Duration.ofSeconds(30))
    .retryBudget(Duration.ofSeconds(20))
    .fallbackBaseUris(List.of(URI.create("https://eu.example.com")))
    .onAttempt(attempt -> System.out.println(attempt.baseUri() + " " + attempt.statusCode()))
    .build();
var client = new ApiClient(options);
```

## Hooks and tracing

`ClientOptions.Builder.hooks(ApiClient.RequestHooks)` observes every call.
Each attempt starts with `beforeRequest` and ends with exactly one of
`onRetry` (another attempt follows), `afterResponse` (the success the call
returns) or `onError` (the failure the call completes with): a call that
succeeds after one retried 503 reports `beforeRequest`, `onRetry`,
`beforeRequest`, `afterResponse`, and a connection failure that is not retried
reports `beforeRequest`, `onError`. Each callback receives an
`ApiClient.HookContext` record with `operationId`, `method`, `url`, `headers`,
`attempt` (from 1), `elapsed` since the call started, `statusCode` once the
server answered, `error` when the attempt or the call failed and `retryDelay`
on `onRetry`; each connection of a stream is one call.

The context is an immutable record: no hook can change the request. It never
carries a credential: `Authorization`, `Proxy-Authorization`, `Cookie`, every
API-key header and every API-key query parameter read `[redacted]` in
`headers` and `url`, and so does every configured credential value found
anywhere else. A hook's own exception ends the call with it.

`ClientOptions.Builder.tracer(ApiClient.RequestTracer)` opens one span per call
through an interface this SDK defines, with no tracing dependency:
`startSpan(operationId, attributes)` receives `http.request.method`, and the
returned `ApiClient.TraceSpan` is ended with `http.request.resend_count` (the
retries) and, when the server answered, `http.response.status_code`. With
`io.opentelemetry:opentelemetry-api` on the classpath, this adapter maps it
onto OpenTelemetry:

```java
import io.opentelemetry.api.GlobalOpenTelemetry;
import io.opentelemetry.api.common.AttributeKey;
import io.opentelemetry.api.trace.Span;
import io.opentelemetry.api.trace.Tracer;
import java.util.Map;

final class OpenTelemetryTracing {
    static ApiClient.RequestTracer tracer(Tracer otel) {
        return (name, attributes) -> {
            Span span = otel.spanBuilder(name).startSpan();
            record(span, attributes);
            return ended -> {
                record(span, ended);
                span.end();
            };
        };
    }

    private static void record(Span span, Map<String, Object> attributes) {
        attributes.forEach((key, value) -> {
            if (value instanceof Number number) span.setAttribute(AttributeKey.longKey(key), number.longValue());
            else span.setAttribute(AttributeKey.stringKey(key), String.valueOf(value));
        });
    }

    static ApiClient.ClientOptions options() {
        return ApiClient.ClientOptions.builder()
            .tracer(tracer(GlobalOpenTelemetry.getTracer("my-service")))
            .hooks(new ApiClient.RequestHooks() {
                @Override public void onRetry(ApiClient.HookContext context) {
                    System.out.println(context.operationId() + " " + context.attempt() + " " + context.statusCode());
                }
            })
            .build();
    }
}
```

## Streaming

Operations declared `x-omniwrap-streaming: sse` (or answering
`text/event-stream`) return `ApiClient.SseStream<T>`: an `Iterable` and
`AutoCloseable` view over the live response whose events carry `id`, `event`,
raw `data`, the decoded `value` and `retry` (the server's reconnection time in
milliseconds). Iterate it (or call `stream()`), read `lastEventId()` and
`reconnects()`, and close it when done; a `[DONE]` data payload ends the
stream, and an event still incomplete when a connection ends is discarded.
NDJSON operations (`x-omniwrap-streaming: ndjson` or `application/x-ndjson`)
return `ApiClient.NdjsonStream<T>`, the same single-use view yielding one
decoded value per non-blank line. `toList()` drains either stream, and
`statusCode()` and `headers()` describe the most recent response.

`RequestOptions.Builder.stream(ApiClient.StreamOptions)` bounds one streaming
call, and a bound out of range is refused with `ApiClient.StreamingException`
before any request: `maxReconnects` (0, the default, through 1000) resumes a
server-sent-event stream whose connection ended without `[DONE]`, sending the
last event id seen as `Last-Event-ID` to the client's own origin only;
`reconnectDelay` (at most 60 seconds, default 1 second) is the wait before a
resumption and is replaced by a server `retry`; `lastEventId` seeds the first
request; `onReconnect` receives an `ApiClient.ReconnectContext` before each
wait; `maxLineLength` (1 through 100000000 bytes, default 1000000) bounds one
event and one NDJSON line, beside the client's `maxResponseBytes` bound on
every line. NDJSON never resumes. A failed resumption request, an exceeded
bound or an undecodable value ends the stream with its exception, and a closed
stream never resumes. WebSocket transport is not generated.

This contract declares no streaming operation.

## Request bodies

JSON bodies are encoded by the bounded `ApiClient.Json` codec, `text/*` bodies
as UTF-8 and `application/octet-stream` bodies as raw `byte[]`.
`multipart/form-data` operations take a `Map<String, Object>` (or a generated
record) whose values become parts through `ApiClient.MultipartBody`: `byte[]`
values become file parts (`application/octet-stream`, the field name as
filename), maps and records become `application/json` parts, collections
repeat the field once per item, and `ApiClient.MultipartBody.Part` values are
sent exactly as built (explicit filename and content type). The boundary is
drawn from `SecureRandom` for every request and re-drawn if it occurs in any
part payload; part names and filenames are escaped like browsers and httpx do
(`"` `CR` `LF` become `%22` `%0D` `%0A`, other UTF-8 is sent verbatim), and a
part content type may not carry control characters. Bodies are buffered in
memory (at most `MultipartBody.MAX_PARTS` parts), so replay-aware streaming
uploads remain a later V3-452 leaf. `application/x-www-form-urlencoded`
operations encode the same map shape through `ApiClient.FormBody` (form style,
exploded: collections repeat the field, object values become top-level fields,
deeper nesting travels as JSON text, UTF-8 percent-encoding); binary values are
rejected there.

Path segments and query values are percent-encoded per RFC 3986 (unreserved
characters kept, everything else including `/` encoded as UTF-8). Object
parameters honour `explode` (`k=v` pairs, or separate query pairs) and the
`deepObject` style (`name[k]=v`).
